# Копия базы снаружи

Раз в сутки выгружает базу целиком и кладёт её **за пределы Firebase**.

## Зачем это нужно

В сервисе есть 17 узлов `*-backups` — снимки, которые снимаются перед каждой
записью списка. Механизм хороший, но все эти снимки лежат **в той же базе**,
которую они должны защищать. Удалили проект, кончилась оплата, утёк служебный
ключ (он обходит правила), запустили кривой restore — и они уедут вместе с
данными. Ручной экспорт JSON из админки есть, но он делается руками, то есть не
делается.

## Куда ложится копия

| Куда | Настройка | Хранится |
|---|---|---|
| Артефакт прогона GitHub | не нужна, работает сразу | 90 дней |
| Google Диск | секреты `GDRIVE_*` (ниже) | `BACKUP_KEEP_DAYS`, по умолчанию 60 дней |

Артефакт — это не «времянка», а полноценная вторая копия в независимом от
Firebase месте. Диск удобнее тем, что копию видно глазами и можно скачать с
телефона.

## Только чтение

Скрипт не пишет в базу ничего. Восстановление остаётся ручным и осознанным
действием владельца: файл распаковывается и заливается через админку. Автоматом
данные не перезаписываются никогда — это прямое правило проекта.

Ещё одна защита: если база вернула пусто, копия НЕ делается. Иначе один сбой
чтения подменил бы хорошую копию пустой, а через сутки её бы уже не осталось.

## Подключить Google Диск

Нужен разовый шаг: Диск должен писать от **твоего** аккаунта, а не от служебного.

Причина техническая, а не бюрократическая: у служебного аккаунта нет своего места
на Диске. Файл, который он создаёт в расшаренной папке, принадлежит ему, а квота
у него нулевая — загрузка падает с «storage quota exceeded». Обходится либо общим
диском (это платный Google Workspace), либо авторизацией живого аккаунта.

1. **Папка на Диске.** Создай папку, открой её и скопируй идентификатор из
   адреса: `drive.google.com/drive/folders/`**`ЭТА_ЧАСТЬ`**.
2. **Доступ к Диску в Google Cloud.** Консоль → проект `titovstroy-da1cf` (он уже
   есть) → APIs & Services:
   * *Library* → включить **Google Drive API**;
   * *OAuth consent screen* → тип External, добавить себя в Test users;
   * *Credentials* → Create credentials → **OAuth client ID** → тип **Web
     application** → в Authorized redirect URIs вписать
     `https://developers.google.com/oauthplayground`.
   Получишь **Client ID** и **Client secret**.
3. **Разовая авторизация.** Открой
   [OAuth Playground](https://developers.google.com/oauthplayground/) →
   шестерёнка справа → *Use your own OAuth credentials*, вставь ID и secret →
   слева выбери scope `https://www.googleapis.com/auth/drive.file` →
   **Authorize APIs** → войди своим аккаунтом → **Exchange authorization code for
   tokens**. Скопируй **Refresh token**.

   Scope `drive.file` даёт доступ только к файлам, созданным этим приложением —
   к остальному Диску оно не притронется.
4. **Секреты в GitHub** (Settings → Secrets and variables → Actions):
   * Secrets: `GDRIVE_CLIENT_ID`, `GDRIVE_CLIENT_SECRET`, `GDRIVE_REFRESH_TOKEN`
   * Variables: `GDRIVE_FOLDER_ID`, при желании `BACKUP_KEEP_DAYS`
5. **Проверить:** Actions → «Копия базы» → Run workflow. В логе будет объём и
   строка «На Диск загружено».

Пока секреты не заданы, прогон отработает и просто напишет, что Диск не настроен
— копия останется в артефактах.

## Как восстановиться

1. Скачать нужный `titovstroy_backup_*.json.gz` (Диск или артефакт прогона).
2. Распаковать: `gunzip titovstroy_backup_2026_09_08_2117.json.gz`.
3. Внутри — вся база одним объектом: ключи узлов, значения — строки JSON, ровно
   как их пишет приложение.
4. Заливать через админку, по нужным разделам. **Целиком поверх боевой базы
   ничего не заливать не глядя** — сначала посмотреть, что в файле, и сверить
   даты.
