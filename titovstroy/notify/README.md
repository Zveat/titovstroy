# Уведомления в Telegram

Служба, которая читает журнал изменений и просрочки и пишет сотрудникам в Telegram.

**Отправляет `../api/notify-run.mjs` на Vercel** — функция читает базу сервисным ключом и
шлёт сама, за секунду-две. Сам движок прогона общий и не знает, где запущен:
`../src/notify/runNotify.js`.

Когда он срабатывает:

| повод | кто зовёт | задержка |
|---|---|---|
| событие в журнале (сменили статус, подписали договор, удалили) | приложение, в момент записи — `../src/notify/instantNotify.js` | ~20 секунд (пауза на сворачивание пачки) плюс секунда на отправку |
| кнопка «Отправить сейчас» в Админке | приложение — `../src/notify/sendNowTrigger.js` | сразу |
| час сводки из Админки | открытая вкладка спрашивает «пора?» раз в минуту — `../src/notify/notifyTicker.js` | до минуты |
| ничего из этого не сработало | прогон GitHub Actions раз в час | до часа |

**GitHub Actions — ЗАПАСНОЙ путь, а не основной.** Любой прогон это выдать машину, выкачать
репозиторий, поставить зависимости — минута только на подготовку, мгновенной отправки из него
не выжать. Плюс расписание GitHub не гарантировано: замерено на боевом — 14 сентября из 96
запрошенных тиков случилось ТРИ. Пропуск сообщения не теряет (курсор в `titovstroy-tg-state`
двигается только по факту отправки), но ждать приходилось часами.

Стоявшая здесь подстраховка `workflow_run` на парсер мастеров не сработала НИ РАЗУ — ноль
прогонов с этим событием за всё время жизни воркфлоу. **Не возвращать её и не привязывать
уведомления к парсеру вообще.**

## Что нужно сделать один раз

1. **Завести бота.** В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot`,
   придумать имя. Он выдаст токен вида `12345:AAH...`.
2. **Положить токен в GitHub.** Репозиторий → Settings → Secrets and variables → Actions →
   New repository secret, имя `TELEGRAM_BOT_TOKEN`, значение — токен.
   Секрет `FIREBASE_SERVICE_ACCOUNT` и переменная `FB_DB_URL` уже есть, они общие с парсером.
3. **Опубликовать правила базы** из `../firebase/database.rules.json` (в них добавлены три
   узла `titovstroy_tg_*`). Без этого настройки не сохранятся.
4. **Включить в Админке.** Вкладка «🔔 Уведомления»: вписать имя бота, включить
   переключатель, отметить кому какие направления.
5. **Подключить людей.** Напротив фамилии — «Подключить», ссылка копируется. Сотрудник
   открывает её и жмёт «Запустить». Отключиться сам может командой `/stop`.
6. **Общий чат** (по желанию): добавить бота в группу, отправить там `/id`, номер вставить
   в Админке.

## Мгновенные ответы бота (webhook)

Прогоны по расписанию годятся для рассылки, но не для разговора с ботом: человек жмёт
«Запустить» и ждёт до часа. Поэтому команды бота (`/start`, `/stop`, `/id`) принимает
отдельная функция на Vercel — Telegram стучится в неё сам, ответ приходит за секунду.
Разбор команд у обоих путей ОБЩИЙ (`handleBotCommand` в модели), чтобы ответы не зависели
от того, каким путём пришло сообщение.

Включается один раз:

1. **Vercel → Settings → Environment Variables** (проект сайта), добавить две переменные:
   * `TELEGRAM_BOT_TOKEN` — тот же токен бота;
   * `TELEGRAM_WEBHOOK_SECRET` — любая длинная случайная строка, придумать самому.
   `FIREBASE_SA_CLIENT_EMAIL` и `FIREBASE_SA_PRIVATE_KEY` там уже есть — они общие со входом.
2. **GitHub → Secrets → Actions**: добавить `TELEGRAM_WEBHOOK_SECRET` с тем же значением
   (иначе включалка не сможет передать его Telegram). Если адрес сайта не
   `https://erp.titovstroy.kz`, завести ещё переменную (Variables) `WEBHOOK_URL` с полным
   адресом функции, например `https://ваш-домен/api/tghook`.
3. **Задеплоить** — код приезжает на Vercel обычным пушем в main.
4. **Actions → «Уведомления в Telegram» → Run workflow → webhook: включить.**

Проверить в любой момент: то же меню, **webhook: проверить**. Telegram покажет СВОЙ взгляд
на бота — какой адрес зовёт, сколько сообщений ждёт доставки и с какой ошибкой он получил
отказ в последний раз. Именно этого не хватало, когда бот молчал: снаружи одинаково
выглядят «никто не писал», «мы не прочитали» и «сервер отказал».

Вернуться к опросу — **webhook: выключить**.

### Почему секрет обязателен

Адрес функции публичный, а сообщение бота — это команда «привяжи вот этот чат к вот этому
сотруднику». Без проверки любой, кто узнал бы адрес, прислал бы поддельный `/start` и
получал бы в свой Telegram сводки с выручкой, валовой и чистой прибылью. Telegram
подписывает каждый запрос заголовком с секретом, функция сверяет его побайтово. **Если
секрет не задан — функция не работает вообще** (отвечает 503): незаданный секрет это
открытая дверь, а не «пока без охраны». Покрыто тестами `../api/tghook.test.js`.

Одновременно webhook и опрос Telegram не отдаёт: пока webhook включён, `getUpdates` в
прогонах отвечает отказом 409. Служба это узнаёт и спокойно пишет в лог, что команды уже
обработаны, — ошибкой это не считается.

## Проверить, не отправляя никому

Actions → «Уведомления в Telegram» → Run workflow → галочка **dry_run**.
В логе будет видно, что и кому ушло бы. Галочка **force_digest** собирает сводку по
просрочкам прямо сейчас, не дожидаясь утра.

## Про безопасность

Служба работает служебным ключом Firebase, а он **обходит правила базы**. Поэтому вся
запись идёт через одну функцию `writeJson`, а она пропускает только два собственных узла
(`assertWritable` в модели). Попытка записать в объекты, сметы, финансы или пользователей
роняет прогон с ошибкой — не портит базу молча. Это покрыто тестами.

Направление «Финансы» отправляет суммы. В общий чат его включать не стоит: суммы увидят
все участники группы.
