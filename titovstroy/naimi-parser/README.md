# Парсер мастеров naimi.kz → база TitovStroy

Собирает мастеров/рабочих с **naimi.kz** (ФИО, ссылка на профиль, рейтинг, отзывы,
верификация, город, виды работ) и пишет их в вашу Firebase-базу под отдельный ключ
`titovstroy-masters`. **Боевые данные сервиса (объекты, финансы, договоры и т.д.) не
затрагиваются** — только свой ключ. Работает бесплатно на **GitHub Actions** (карта и
Blaze не нужны).

## Как это устроено
- Справочники (города, категории, услуги) берутся с публичного JSON-API naimi.
- Список мастеров считывается через headless-браузер (Playwright), который **перехватывает
  ответ API самого сайта** — это устойчивее, чем разбирать HTML по классам.
- Данные нормализуются, дедуплицируются (один мастер — несколько услуг объединяются)
  и пишутся в базу в том же формате, что читает CRM.

## Управление из сервиса (без токенов)
Раздел «🔎 Мастера» в CRM (у Админа) → блок **«⚙️ Настройки обновления»**: частота
(Выключено / Раз в день / 2 раза / Раз в неделю), города, телефонов за прогон, и кнопка
**«🔄 Обновить сейчас»**. Настройки пишутся в ключ базы `titovstroy-masters-config`.

Workflow крутится **каждые 2 часа**, но сначала запускает `check.mjs`, который читает эти
настройки и решает, парсить ли сейчас (по частоте / по кнопке «Обновить сейчас»). Если нет —
прогон завершается за ~минуту (тяжёлые шаги пропускаются, Actions-минуты почти не тратятся).
Поэтому «Обновить сейчас» срабатывает не мгновенно, а в течение ~2 часов.
Ручной запуск с самого GitHub (Run workflow) парсит всегда, игнорируя частоту — удобно для теста.

## Разовая настройка (один раз, ~5 минут)

### 1. Сервисный аккаунт Firebase (ключ для записи в базу)
1. Firebase Console → ⚙️ **Project settings** → вкладка **Service accounts**.
2. Кнопка **Generate new private key** → скачается JSON-файл.
3. В репозитории GitHub: **Settings → Secrets and variables → Actions → New repository secret**:
   - **Name:** `FIREBASE_SERVICE_ACCOUNT`
   - **Secret:** вставить **всё содержимое** скачанного JSON-файла.

> Этот ключ даёт запись в базу в обход правил — храните только в Secrets, никуда не коммитьте.

### 2. (необязательно) Переменные конфигурации
**Settings → Secrets and variables → Actions → Variables → New repository variable**:
| Переменная | Зачем | По умолчанию |
|---|---|---|
| `FB_DB_URL` | URL базы | боевая `titovstroy-da1cf` |
| `MASTERS_KEY` | ключ в базе | `titovstroy-masters` |
| `CITIES` | города (слаги через запятую) | `almaty` |
| `CATEGORY_IDS` | категории каталога | `47` (Ремонт) |
| `MAX_PAGES` | глубина пагинации списка | `6` |
| `FETCH_PHONES` | докапывать телефоны (`1`/`0`) | `1` |
| `PHONES_PER_RUN` | номеров за один прогон | `25` |
| `PHONE_DELAY_MIN_MS` | мин. пауза между номерами | `4000` |
| `PHONE_DELAY_MAX_MS` | макс. пауза между номерами | `11000` |

Слаги городов: `almaty`, `astana`, `shymkent`, `karaganda`, … (полный список отдаёт
`https://apipub.naimi.kz/app/pub/reference/city/list`).

### 3. Первый запуск (проверка)
1. GitHub → вкладка **Actions** → workflow **«Парсер мастеров naimi.kz»** → **Run workflow**.
2. Для теста поставьте `max_services = 2` — пройдёт быстро.
3. Откройте лог: строка **`· эндпоинт списка: …`** покажет реальный API-адрес, а
   **`ИТОГО уникальных мастеров: N`** — сколько собрано.
4. Дальше он идёт по расписанию (по умолчанию — понедельник утром). Расписание меняется
   в `.github/workflows/naimi-parser.yml` (строка `cron`).

## Телефоны — медленный докап (важно про тайминги)
Номер на naimi спрятан за кнопкой (отдельный запрос, который сайт отслеживает и лимитирует —
именно чтобы номера не выкачивали пачками). Поэтому парсер **не берёт всё разом**, а
**докапывает по чуть-чуть**:
- За один прогон подтягивает номер только у `PHONES_PER_RUN` мастеров (по умолч. 25),
  и только у тех, у кого номера ещё нет (уже собранные не трогает).
- Между номерами — случайная **человеческая пауза** `PHONE_DELAY_MIN_MS…MAX_MS` (4–11 сек).
- Запрос идёт из сессии живого браузера (с cookies) — выглядит как обычный «показать телефон».
- Запуск ежедневный → за неделю набегает ~175 номеров, за месяц ~750 — без всплеска, который
  вызывает блокировку. Хочешь быстрее/медленнее — крути `PHONES_PER_RUN` и паузы.

Если хочется совсем аккуратно — оставь дефолт. Если поймаешь `HTTP 401/403` в логе телефонов —
значит номер отдаётся только авторизованным: тогда встроим разовый вход по твоему аккаунту naimi
(логин по коду), и докап продолжится под сессией.

## Уважение к сайту / право
- Не снижай паузы агрессивно и не увеличивай `PHONES_PER_RUN` до сотен — смысл именно в
  постепенности.
- **ToS/право:** naimi.kz — чужой ресурс со своими условиями использования и персональными
  данными людей. Использование — под вашу ответственность и только для внутренних нужд
  (поиск подрядчиков), не для перепродажи/рассылок.
- **Если мастеров собралось 0:** структура ответа API могла измениться — пришлите мне строку
  `эндпоинт списка` из лога, поправлю разбор полей за минуту.
