Что за проект

CRM для ремонтно-отделочной компании «TitovStroy» (Казахстан). React + Vite + Firebase Realtime Database.
Логика — в titovstroy/src/App.jsx (~13 000 строк) + titovstroy/src/production/ProductionModule.jsx
(модуль производства, встраивается в «Объекты» через <ProductionModule embedObjectId embedTab clientInfoCard/>).
Хранилище — обёртка storage (Firebase RTDB + localStorage-резерв), ключи titovstroy-*.
Firebase-ключи санитизируются: всё кроме [a-zA-Z0-9_] → _ (вложенные пути через / не работают).

Окружения — ВАЖНО





Прод: Firebase-проект titovstroy-da1cf, ветка main. Нет VITE_FB_* → код берёт зашитый _FB_PROD. Без метки «🧪 ТЕСТ».



Dev: своя Firebase-база + ветка objects-refactor → Vercel Preview, VITE_FB_* заданы → IS_DEV_ENV=true, метка «🧪 ТЕСТ · dev-база».



firebaseConfig = IS_DEV_ENV ? _FB_ENV : _FB_PROD. Боевую базу и main не трогаем без подтверждения владельца.



Доставка изменений

git push в этом окружении заблокирован (403) — и обычный git, и GitHub API (create_branch/push_files
через MCP тоже 403 «Resource not accessible by integration»). Единственный рабочий путь:





Правим код, собираем (npx vite build должен проходить), гоняем npx vitest run.



Отдаём изменённые файлы владельцу через SendUserFile — он сам заливает на GitHub

(Add file → Upload files, перетащить файлы по тем же путям — заменяет, не дублирует).

Коммиты локально делаем для истории; «Unverified» на GitHub — норм, не подписать и не запушить всё равно.

Неочевидные ловушки (сюда стоит заглянуть перед правкой статусов/производства)





unifiedStatusOf(o): статус объекта для ОТОБРАЖЕНИЯ/фильтра — если у объекта есть карточка
производства со статусом active/paused/done/cancel, он ПЕРЕВЕШИВАЕТ object.status (нужно для старых
объектов, где реальный статус исторически жил в производстве). Кнопки статуса на карточке объекта
пишут object.status через saveObjField, который ЗЕРКАЛИТ выбор в production.prodStatus
(DEAL_TO_PROD) — если этого не сделать, клик по кнопке визуально ничего не меняет (уже дважды
ловили этот баг). computeIssues и «signed→финпроект» смотрят на сырой object.status.



Финпроект заводится авто при статусе «Договор подписан» (saveObjField, СНАЧАЛА создаёт
финпроект+производство, потом меняет статус — иначе при сбое сети объект зависает «подписан» без них),
либо вручную («💰 В финансы»/«В проект»/«+ Проект»). Ключ проекта — номер основного договора.



Облако: если SDK (WebSocket) не отвечает — есть REST-фолбэк (_fbRestSet/_fbRestGet) на тот же
ключ через HTTPS. Баннер «облако недоступно» гаснет сам, когда dirtyKeys()===0.



Роли: admin/manager видят финансы везде (manager — readonly); foreman — только внутри своих
объектов; user (замерщик) — только в смете при заполнении, нигде больше; viewer — только чтение.
